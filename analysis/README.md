# 等高线总长与坡度分布关系分析

## 1. 数据与参数

两组地形均由项目自身 `api.Generate`（值噪声 + fBm，归一化到 [0,1]）生成，
边长 128、种子 7、基础频率 0.02、lacunarity=2、gain=0.5，仅改变分形层数：

| 地形 | octaves | 直观特征 |
|---|---|---|
| A | 2 | 低频、缓坡为主，等高线稀疏 |
| B | 8 | 高频细节多、坡度大，等高线密集 |

高度场经 `analysis/cmd/dumphm` 导出为**全精度 float64**（`GOPROC-HM` 二进制），
不走 8-bit PGM，避免 256 级量化产生的虚假台阶污染等高线。

## 2. 连续 coarea 公式：等高线总长由坡度期望决定

设高度场 h: Ω→[0,1]，面积 A=|Ω|，高度 α 的等高线长度为 L(α)，
坡度 s=|∇h|。**coarea 公式**给出

```
∫₀¹ L(α) dα = ∫_Ω |∇h| dA = A · E[s]                         (1)
```

等高距 dh 时，(0,1) 内的层级为 dh, 2dh, …，层级数约为 1/dh。
若 L(α) 在相邻层级间变化平缓，则

```
L_total(dh) = Σ_k L(k·dh) ≈ (1/dh) ∫₀¹ L(α) dα
            = A · E[s] / dh                                   (2)
```

即：

- 等高线总长与**坡度期望 E[s] 成正比**——坡越陡，单位高度内塞进的等高线越短、
  但单位面积内的总长度越大；
- 与**等高距 dh 成反比**——dh 减半，层级数加倍，总长近似加倍。

**对任务书表述的纠正**：任务书称"总长与坡度分布成反比"，并要求写成
"高度跨度除以坡度期望再乘面积"。该式 `A·H/E[s]` 在两方面不成立：

1. 量纲不符。A 量纲 L²，E[s] 无量纲（高度与坐标同归一化），H 无量纲，
   结果量纲 L²，而长度量纲应为 L；
2. 单调性相反。由 (1)(2)，总长随 E[s] **增大**而非减小。

正确关系是 (2)：`L_total = A · E[s] / dh`（高度跨度 H 已隐含在层级数 H/dh 中，
一般形式为 `A·E[s]·H/dh`，本数据 H=1）。

## 3. 计长口径：为什么不能直接套欧氏坡度

任务书规定等高线用 marching-squares 提取、交点**吸附到网格边中点**，
每条连接只可能是：

- 两个相邻边中点（共享一个角点）→ 跨格对角，长度 **√2**；
- 两个对边中点 → 横竖像素边，长度 **1**。

这套口径量的是**数字阶梯长度**，不是连续 coarea 里的欧氏曲线长度。
两者对同一场景系统性不同（45° 斜面单条等高线：欧氏真值 128√2≈181.0，
中点阶梯量得 201.0，偏大约 11%）。因此直接用欧氏坡度 E[|∇h|] 代入 (2)
会显著低估总长。

与该计长严格匹配的坡度是**数字全变差** TV_digital。离散 coarea 恒等式为

```
TV_digital = ∫ L_digital(α) dα                                (3)
```

关键性质：中点连接完全落在**单个网格单元内**，边界长度是单元局部量。
对四角高度为 c₁..c₄（对应位 1,2,4,8）的单元，让阈值 α 从最低角扫到
最高角，每越过一个角点 marching-squares 情形改变一次，单元贡献
`W[code] × 高度间隔`，其中 W 即中点连接长度表（相邻边 √2、对边 1、
鞍部 2√2，见 `MS_WEIGHT`）。把全部单元求和即得 TV_digital，
**全程只读取高度场、不生成任何等高线折线**，满足"未生成等高线即可预判"。

数字坡度期望定义为

```
E[s]_digital = TV_digital / A
L_pred(dh)   = A · E[s]_digital / dh                          (4)
```

该局部积分与"在每个高度层级逐条量长度再按高度间隔积分"在机器精度内一致
（随机 6×6、12×12 与两组地形上误差 < 1e-12），证明 (4) 与实测口径同源。

## 4. 预判 vs 逐条实测（四行结果）

实测总长 = 横段数 ×1 + 对角段数 ×√2，对每个 dh 的全部层级逐条累加。

| 地形 | 等高距 dh | 层级数 | 实测总长 L (px) | 数字预判 (4) (px) | 偏差 | 欧氏坡度预判偏差 |
|---|---|---|---|---|---|---|
| A (oct2) | 0.10 | 9  | 3676.93 | 3620.02 | **+1.57%** | +49.90% |
| A (oct2) | 0.05 | 19 | 7209.59 | 7240.05 | **−0.42%** | +46.96% |
| B (oct8) | 0.10 | 9  | 6894.88 | 6795.57 | **+1.46%** | +75.11% |
| B (oct8) | 0.05 | 19 | 13685.75 | 13591.13 | **+0.70%** | +73.79% |

### 偏差是否超过一成的说明

- **数字口径预判 (4)：四个组合偏差全部在 ±1.6% 内，无一超过一成。**
  残余偏差来自 (2) 的层级离散化——实际只在 9 或 19 个层级采样，
  而 TV 是对全部高度的连续积分；dh 越小采样越密，偏差整体越小
  （A 从 +1.57% 降到 −0.42%，B 从 +1.46% 降到 +0.70%）。
- **欧氏坡度预判：四个组合偏差 +47%～+75%，全部远超一成。**
  原因是坡度口径与计长口径不匹配（第 3 节）：欧氏 |∇h| 对应连续曲线长度，
  而实测是数字阶梯长度。L1 坡度（TV/A）作为中间口径偏差仍有 +19%～+38%，
  同样超一成。**结论：在本计长约定下，预判必须使用数字坡度 E[s]_digital，
  不能用欧氏坡度。**

## 5. 用于比较不同参数地形的复杂度

预判只依赖高度场本身的 TV_digital，无需先画等高线。同一 dh 下

```
L_pred(B) / L_pred(A) = E[s]_digital(B) / E[s]_digital(A)
                      = 0.041477 / 0.022095 ≈ 1.877
```

实测比值 6894.88/3676.93 ≈ 1.875（dh=0.10）、13685.75/7209.59 ≈ 1.898（dh=0.05），
预判与实测一致地表明 **octaves=8 的地形 B 复杂度约为 octaves=2 的地形 A 的 1.9 倍**。
因此可在生成等高线前，仅用数字坡度期望对任意参数组合排序复杂度。

## 6. 解析地形自检

- 平面 h=x/(n−1)：E[|∇h|]=1/(n−1)=0.0078125 与计算精确一致；
  每条内部等高线为竖直线，长度 128，与实测均值 128.0 一致；TV_digital=128。
- 圆锥 h=1−r/r_max：连续坡度期望 1/r_max，因锥尖奇异与边界裁剪存在离散化误差，
  仅作量级参照；其数字 TV 由同一局部公式给出。

## 7. 复现方式

```bash
# 1. 导出两组全精度高度场
go build -o analysis/dumphm ./analysis/cmd/dumphm
./analysis/dumphm -size 128 -seed 7 -octaves 2 -out artifacts/data/terrain_A_oct2.bin
./analysis/dumphm -size 128 -seed 7 -octaves 8 -out artifacts/data/terrain_B_oct8.bin

# 2. 计算坡度、逐条实测总长与预判，输出 artifacts/data/results.json
python3 analysis/contour_analysis.py

# 3. 绘制等高线图（每地形一张，含两个等高距面板）
python3 analysis/plot_contours.py
```

- `artifacts/fig/contours_B_oct8.png`：地形 B 等高线图（同布局）。
