# 流向判定的数学证明与离散规则

本文证明三件事：

1. 每格的流向只由该格与其八邻格的高度梯度决定，梯度方向离散到八邻域后有唯一、可复算的判定规则；
2. 按该规则可以一次扫描预判全图流向，并在线性时间内结算每格的汇流终点，无需迭代累积；
3. 预判结果与逐格追踪必然逐格一致，比对方法与零坡度格的处理另行说明。

记号：高度图为 `h(x,y)`，网格边长 `S`，格子总数 `N=S²`，坐标取像素整数格点。

## 1. 流向只由高度梯度决定

### 1.1 连续情形

地表水流在忽略惯性、扩散与下渗时，单位质量水体沿重力势能下降最快的方向运动。势能与高程 `h` 成正比，故流速方向取高程的最速下降方向：

$$
\mathbf{v} \propto -\nabla h = -\left(\frac{\partial h}{\partial x},\ \frac{\partial h}{\partial y}\right)
$$

即流向是高度场负梯度方向，**只由局部一阶导数（梯度）决定**，与远处地形、路径历史无关。

### 1.2 网格上的离散化（D8 规则）

规则网格上没有连续方向，只能走向八个相邻格。对中心格 `c=(x,y)` 与邻格 `n_d`（`d∈{0..7}`，顺序 E, SE, S, SW, W, NW, N, NE），定义离散坡度：

$$
g_d = \frac{h(c)-h(n_d)}{L_d},\qquad
L_d =
\begin{cases}
1 & \text{正方向（E/S/W/N）}\\
\sqrt{2} & \text{斜方向（对角）}
\end{cases}
$$

`g_d` 正是负梯度在方向 `d` 单位向量上的有限差分投影。最速下降方向离散为坡度最大的邻格：

$$
d^*(c)=\arg\max_d g_d,\qquad \text{仅在 } g_d>0 \text{ 的邻格中选取}
$$

实现见 `internal/flow/flow.go` 的 `Direct`：

- 落差 `drop = h(c) - h(n_d) ≤ 0` 的邻格直接排除，只接受严格更低格；
- 斜方向落差除以 `√2`，保证正、斜方向按单位距离坡度公平比较；
- 取得严格最大坡度的方向即流向。

### 1.3 并列的确定性裁决（可复算性）

浮点高度下两个坡度可能严格相等，`argmax` 不唯一。规定固定全序裁决：**并列时取方向编号最小者**（编号顺序 E=0, SE=1, …, NE=7，即顺时针，正方向先于相邻斜方向）。代码以严格大于 `slope > bestSlope` 替换当前最优实现，天然保留先遇到的小编号方向。

因此任意一格的流向是其 3×3 邻域高度的确定性函数，与计算顺序、全局状态无关，任何人按同一规则都能逐格复算出同一结果。

## 2. 零坡度格子单独处理

若八个邻格都不严格低于中心格，则 `max g_d ≤ 0`，不存在严格下降方向，`Direct` 返回 `Sink(255)`。它包含两类：

- **内陆汇（洼地/局部低点）**：邻格全部更高或等高，水在此蓄积，不指派流出方向；
- **平地/平台**：八邻格全部等高，梯度为零向量，连续意义下本就无方向。

这类格子在 `FlatCells` 中单独枚举统计，不参与方向行走，是流路的天然终点。边界上的 `Sink` 格按第 4 节的终点约定仍计为出口（水已在画幅边缘）。

把零坡度格与有坡格分开处理，避免了在平地上人为指定方向或引入收敛迭代，规则对所有格子保持封闭。

## 3. 一次性预判全图，无需迭代累积

### 3.1 流向可一次扫描算出

`Direct(c)` 只读 `c` 的八个邻格高度。对任意两格 `c₁≠c₂`，判定 `Direct(c₁)` 不写、也不读 `c₂` 的判定结果，格间无数据依赖。因此：

$$
\{\,d^*(c): c\in G\,\}
$$

可在对全图的一次行优先扫描中全部求出，复杂度 `O(N)`，对应 `flow.Build`。这里没有任何跨格迭代或累积量（不像流量累积需要反复传播），每个格子的结论在访问到它时即最终结论。

### 3.2 终点结算为函数图上的记忆化搜索

给每格指派至多一个出边（流向）或无边（Sink），全图构成一张**函数图** `f: G → G∪{⊥}`。

**引理（无环）**：图中不存在有向环。

证明：每条出边都由 `Direct` 指向严格更低格，故沿任意出边高度严格下降。若存在环 `c₀→c₁→…→cₖ→c₀`，则
`h(c₀)>h(c₁)>…>h(cₖ)>h(c₀)`，矛盾。∎

无环函数图的每个弱连通分量至多有一个汇点（无边格），或其指针走出边界。每格的追踪终点（首个边界格＝出口，或到达的 Sink＝内陆汇）唯一。`ResolveAll` 用记忆化深度优先：沿指针行走并记录路径，一旦遇到已结算格或终点，就把同一终点一次性回填给路径上所有格。每格至多入队、回填各一次，总复杂度 `O(N)`，额外空间 `O(N)`。

### 3.3 与迭代累积的区别

流量累积（flow accumulation）需要把上游贡献沿图反复传播，是迭代/递归累积过程；本问题只问每格**流向哪里终止**，答案在函数图结构确定（即第 3.1 节一次扫描）后就已固定，记忆化只是把共享后缀的行走结果复用，不改变任何格子的方向，故无需迭代累积。

## 4. 终点（出口/汇）定义与逐格追踪的等价性

逐格追踪参照实现 `NaiveTrace`：从 `(x,y)` 起，每步对当前格重新调用 `Direct` 行走；

- 首次到达边界格（`x=0` 或 `y=0` 或 `x=S-1` 或 `y=S-1`）即停止，记为**出口** `TermOutlet`；
- 到达 `Sink` 即停止，记为**内陆汇** `TermSink`。

**定理**：`ResolveAll` 给出的终点与 `NaiveTrace` 对每一格都相同。

证明：两者沿同一条由 `Direct` 唯一确定的出边链行走。`NaiveTrace` 每步现场重算 `Direct`，而 `ResolveAll` 走的是 `Build` 预先算好并存下来的同一个 `Direct` 值；由第 1.3 节的确定性，两者在每个格子上取到的方向完全相同。又由无环引理，两条行走都在有限步内停于同一个边界格或同一个 Sink。故终点逐格相同。∎

边界格一律先判出口再判方向，因此边界上的 Sink 也计为出口；这一约定对两个实现完全一致，不影响等价性。

## 5. 验证方法

`cmd/flowdemo` 对两个画幅分别：

1. `flow.Build` 一次扫描预判全图流向，存 PGM（灰度 `dir*32+1`，取值 1..225，Sink 为 0，规则写在 PGM 头注释，可反向解码复算）；
2. `flow.ResolveAll` 线性结算每格终点；
3. `flow.NaiveTrace` 对全部 `N` 格逐格重算追踪；
4. 两结果逐格比对，任何不一致都输出坐标及双方终点；
5. 出口数、出口坐标、内陆汇坐标按行列出；零坡度格数量单列。

单元测试 `internal/flow/flow_test.go` 另以手工小网格验证：正/斜方向距离归一化、并列裁决、零坡度全 Sink、边界出口、两种追踪逐格一致、无环（高度沿边严格下降）、PGM 编解码往返。

### 5.1 为什么复算必须用原始 float64 而不是 PGM 高度

高度 PGM 把归一化高度量化到 256 级（`internal/hmap`），舍入误差会改变近并列邻格的落差次序。实测两个画幅上，用量化后的 PGM 高度重算 D8 分别有约 11% 与 9% 的格子方向翻转；这些翻转不是规则错误，而是输入精度损失。因此：

- 流向判定与逐格比对始终在**原始 float64 高度**上进行；
- `flowdemo` 额外落盘 `height_*.f64`（小端、行优先、每值 8 字节），供外部工具无损独立复算；已用与 Go 实现无关的 Python 脚本对 f64 数据重算 D8，两画幅均零不一致；
- 流向 PGM 本身是**无损**的（8 个方向 + Sink 共 9 个离散值，灰度映射可逆），可放心存档与解码；
- 高度 PGM 仅用于可视化，不作为流向复算的输入。
