# 曲率脊线检测与总数预判

在 goproc 高度图上按横截面曲率的一维极小检测脊线像素，并由全图差分分布
预判脊线像素总数。判定与预判都不需要逐条追踪脊线。

```
go run ./cmd/ridge run --sizes 128,256 --seed 1 --out artifacts/ridge
make ridge
python3 -I tools/verify_ridge.py artifacts/ridge 128
```

产物（`artifacts/ridge/`）：

| 文件 | 内容 |
|---|---|
| `report.txt` | 两个画幅各一行的预判/实测对照，含偏差超一成的点名 |
| `ridge_mask_N.pgm` | 脊线掩码，白=脊线像素 |
| `ridge_components_N.pgm` | 按连通段着色（前十段分级，其余中灰） |
| `height_N.pgm` | 8 位高度图，仅供目视 |
| `height_N.f64` | 小端 float64 高度，供独立复核 |

## 1. 判定：极值检测化成一维符号翻转

横截面曲率用二阶中心差分

```
κ(x, y) = h(x−1, y) − 2h(x, y) + h(x+1, y)
```

候选列 `x ∈ [2, N−3]`，判据为左右差分的符号翻转

```
dL = κ(x) − κ(x−1),   dR = κ(x+1) − κ(x),   脊线像素 ⇔ dL < 0 < dR
```

最左、最右各两列缺少完整邻域，不参与判定，故候选像素数为 `N² − 4N`。
`dL` 或 `dR` 恰为零的位置不属于严格极小，计入 `ties` 而不计入脊线；
实测值为零，见报告。

## 2. 预判：用差分分布替代逐条追踪

记相邻差分 `D_i = κ(i+1) − κ(i)`。候选列 `x` 的判据只依赖 `(D_{x−1}, D_x)`，
因此全图脊线数等于所有相邻对异号且左负右正的对数。在零均值、等方差的
联合高斯近似下

```
P(D_left < 0 < D_right) = 1/4 − arcsin(ρ)/(2π)
预判总数 = P × 候选像素数
```

`ρ` 由全图差分对一次算得（`pairStatsOf`），不需要逐条追踪。`ρ = 0` 时为 `1/4`，
`ρ → 1` 时为 0，`ρ → −1` 时为 `1/2`，与一维随机游走的直觉一致。

若只用曲率边际分布、假设相邻列独立，任意连续分布下中间点严格最小的概率都是
`1/3`。这条更朴素的预判在默认参数下高估约一倍（报告中的「独立同分布对照」），
因为相邻曲率强正相关（`ρ ≈ 0.45`）。这解释了为什么必须用差分对的联合分布，
而不能只用边际分布。

## 3. 「脊线必在曲率取极小处」不成立

作为几何命题，这个前提是假的。一维反例：

```
h(x) = exp(−x²/2) + 0.35·exp(−(x−1.5)²/0.4)
```

高度极大在 `x ≈ 0.01`，曲率极小却在 `x ≈ 1.49`。曲率小刻画的是「平坦或陡峭」，
不是「高或低」；曲率极小可以是山脊、谷底、肩部或斜坡的拐折。

在默认高度场上实测，两类像素的重合率只有约一成：

| 画幅 | 曲率极小 | 高度极大（分水脊） | 重合 | P(分水\|曲率) | P(曲率\|分水) |
|---|---|---|---|---|---|
| 128² | 2818 | 785 | 306 | 10.9% | 39.0% |
| 256² | 11348 | 3080 | 1069 | 9.4% | 34.7% |

因此曲率公式只能预判「曲率脊」的数目，**不能**用它预判地形山脊的数目。
报告里另列一条「分水脊」判定（高度 `h(x)` 的局部极大，同样化成一维符号翻转），
单独做预判比对，避免把两种「脊」混为一谈。

## 4. 结果

`seed=1, octaves=4, gain=0.5, freq=0.02`：

| 画幅 | 曲率预判 | 曲率实测 | 偏差 | 分水预判 | 分水实测 | 偏差 |
|---|---|---|---|---|---|---|
| 128² | 2808.8 | 2818 | −0.33% | 779.7 | 785 | −0.67% |
| 256² | 11366.9 | 11348 | +0.17% | 3156.7 | 3080 | +2.49% |

两个画幅、两种判定都远在一成以内。多种子、多画幅的稳健性见
`TestPredictionRobustAcrossSeeds`；默认参数下，128²/256²/512² 各取 4 个种子，
曲率脊偏差在 −0.3%~+1.1%，分水脊在 −0.7%~+5.8%。

### 假设失效时会怎样

公式的前提是差分对近似联合高斯。实测超额峰度约 0.4–0.6、偏度约 0，
还算接近高斯；但换成低层数、低频率的参数（如 `octaves=1, freq=0.01`），
地形近乎一张平滑曲面，曲率沿横截面近乎常数（差分 ρ=0.962）、峰度 6.6、偏度 2.1，
符号翻转退化成空集或极少点：该例预判 697，实测 193，偏差 +261%；分水脊实测为 0。
此时报告在「偏差超过一成的画幅」下点名，并列出「前提失效」的具体统计量。
这类参数不是「预判不准」，而是判定本身在该参数下退化。

扫描到的失效边界（128²，seed=1，`freq ≤ 0.01` 或 `octaves ≤ 2` 且 `freq ≤ 0.02` 时
偏差普遍超过一成）：`octaves=4, freq≥0.02` 与 `octaves=3, freq=0.04` 等参数下偏差回到一成以内。

## 5. 总长

脊线总长取每个连通段内相邻像素的最小生成树边长（直步 1、对角 √2），
是折线长度的下界，单像素段计 0。128² 为 2750 像素（0.976/像素），
256² 为 11074 像素（0.976/像素），比例稳定。

## 6. 数值注意

- 8 位 PGM 的量化步长约 `3.9e-3`，大于默认参数下曲率均值 `3.5e-3`。
  从 `height_*.pgm` 复算会把曲率压成十几个取值并制造大量并列，
  实测会从 2818 跳到 4442。**独立复核必须用 `height_*.f64`。**
- 判定与预判都在浮点高度上做，`tools/verify_ridge.py` 不引用 Go 代码，
  从浮点数据重算并与掩码逐像素比对，结果一致。
